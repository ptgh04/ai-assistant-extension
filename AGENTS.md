# AGENTS.md

## Package manager & runtime

Use **Bun** exclusively for all package management, script running, and testing. NEVER use `npm`, `yarn`, or `pnpm`.

The stack is WXT 0.19, React 19, Tailwind CSS v4 (via `@tailwindcss/vite`), Zustand, and TypeScript. The lockfile is `bun.lock`.

- Install dependencies: `bun install` (runs `postinstall: wxt prepare`, which generates `.wxt/`)
- Dev server: `bun run dev` (launches a dedicated Chrome instance with HMR; `bun run dev:firefox` for Firefox)
- Production build: `bun run build` (output: `.output/chrome-mv3`); use `bun run build:firefox` for Firefox and `bun run zip` for a store package
- Typecheck: `bun run compile` (runs `tsc --noEmit`)

There are no lint, test, or format scripts and no CI workflows configured yet. `bun run compile` is the only automated verification step.

**Important:** `tsconfig.json` extends `./.wxt/tsconfig.json`, which is generated by `wxt prepare`, and maps `@/*` to `./src/*`. If typecheck fails with missing config, run `bun install` first. Never edit `.wxt/` — it is generated.

## Architecture

Chrome MV3 extension built with **WXT** (Vite-powered). React 19 + Tailwind CSS v4 + Zustand. TypeScript strict mode with `@/*` path alias → `./src/*`.

- `entrypoints/` — WXT extension entry points (`background.ts`, `content.ts`, `sidepanel/`). This is where execution starts, not in `src/`; `background.ts` is the service worker and controls side-panel behavior.
- `wxt.config.ts` — manifest (permissions, host permissions for OpenAI/Anthropic/Gemini APIs), Vite plugins.
- `src/` — domain code split into 8 bounded contexts: `identity`, `conversation`, `page-context`, `interaction`, `ai-backend`, `skill-engine`, `agentic`, `generation`. These are currently scaffold stubs (`index.ts` with `export {}`); put new code in the matching context directory.

### Domain docs (read before working in a context)

- `CONTEXT.md` — domain vocabulary and invariants, including BYOK-only behavior, the vault, `RiskLevel`, and `Forbidden`. Use its exact terms (e.g. `ActionProposal`, `RiskLevel`, `ThreadAttachment`) in issues, code, and tests; don't drift to synonyms.
- `docs/adr/ADR.md` — architectural decision records. Changes to core domain entities or cross-cutting security invariants require an ADR discussion/PR **before** implementation. If your work contradicts an ADR, surface it explicitly.
- See `docs/agents/domain.md` for the full docs layout.

## Git workflow

See `CONTRIBUTING.md` for the complete workflow.

- Conventional Commits: `<type>(<scope>): <summary>`. Types: `feat`, `fix`, `test`, `refactor`, `docs`, `chore`, `perf`. Scopes match the bounded contexts (e.g. `feat(agentic): ...`).
- Branch naming: `feature/<issue-#>-<username>-<desc>`, `fix/...`, `refactor/<scope>-...`, `spike/...`.
- Claim an issue before branching: `gh issue edit <issue-number> --add-assignee @me`.
- Base branch is `main`; rebase frequently (`git pull --rebase origin main`), keep branches < 48 hours old.
- PRs link the issue (`Closes #12`); merges via **Squash and Merge**. PR template requires selecting the bounded context.

## Temporary directory

Use the gitignored `temp/` folder in the project root for temporary files. If it does not exist, ask the user for permission to create it first. NEVER use the system temp directory, user app-data directories, or the agent brain/scratch directory for project-related temp files.
